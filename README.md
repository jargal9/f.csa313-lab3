## SLO ба Error Budget тооцоо

| Сценарио | SLI (Хэмжих зүйл) | Босго (Threshold) | Цонх / Нөхцөл |
| :--- | :--- | :--- | :--- |
| Performance  | `/cart/add` latency p95    | **< 50 ms** | 20 VU, 1 мин          |
| Reliability  | `/pay` error rate          | **< 8%**    | 20 VU, 1 мин          |
| Availability | бүх хүсэлтийн success rate | **≥ 90%**   | 2 мин, 10 сек зогсолт |

## Босго сонгосон үндэслэл: 

* Performance — 50 ms: /cart/add нь локал сервер дээр маш хурдан хариу өгдөг endpoint бөгөөд бодит туршилтаар p95 нь ойролцоогоор 1–2 ms байсан. Тиймээс 200 ms босго хэт сул байж болох тул 50 ms-ийн босго сонгосон.
* Reliability — 8%: /pay endpoint-д серверийн түвшинд ойролцоогоор 5% санамсаргүй 500 алдаа үүсгэхээр тохируулсан. Иймээс 5%-иас бага биш, бага зэрэг нөөцтэй 8%-ийн босго сонгосон.
* Availability — 90%: Chaos туршилтаар серверийг 10 секунд зогсоох тул нийт хүсэлтийн дор хаяж 90%-ийг амжилттай боловсруулах шаардлага тавьсан.

## Error Budget тооцоо:
Availability SLO нь 90% тул зөвшөөрөгдөх алдааны хувь: 2 минутын (120 секунд) цонхонд 90% availability гэдэг нь 10%-ийн алдах эрх буюу 12 секундийн "эвдрэх эрх"-ийг цагаар илэрхийлж байна.
