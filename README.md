## SLO ба Error Budget тооцоо

| Сценарио | SLI (хэмжих зүйл) | Босго (threshold) | Цонх / нөхцөл |
| :--- | :--- | :--- | :--- |
| Performance | `/cart/add` latency p95 | **< 50 мс** | 20 VU, 1 минут |
| Reliability | `/pay` error rate | **< 8%** | 20 VU, 1 минут |
| Availability | Бүх хүсэлтийн success rate | **≥ 90%** | 2 минут, 10 секундийн зогсолт |
| Performance нэмэлт | `/report` latency p95 | **< 450 мс** | 20 VU, 1 минут |

### Босго сонгосон үндэслэл

- **Performance — 50 мс:** `/cart/add` нь локал сервер дээр маш хурдан хариу өгдөг endpoint бөгөөд бодит туршилтаар p95 нь ойролцоогоор 1–2 мс байсан. Тиймээс 200 мс-ийн босго хэт сул байж болох тул 50 мс-ийн босго сонгосон. `/report` endpoint-ийн хэвийн ажиллагааны хурд болон ачааллын үеийн гүйцэтгэлд үндэслэн `p(95) < 450 мс` threshold сонгосон.
- **Reliability — 8%:** `/pay` endpoint-д серверийн түвшинд ойролцоогоор 5% санамсаргүй `500` алдаа үүсгэхээр тохируулсан. Иймээс бага зэрэг нөөцтэй 8%-ийн босго сонгосон.
- **Availability — 90%:** Chaos туршилтаар серверийг 10 секунд зогсоох тул нийт хүсэлтийн дор хаяж 90%-ийг амжилттай боловсруулах шаардлага тавьсан.

### Error Budget

Availability SLO нь 90% тул 2 минутын (120 секунд) цонхонд зөвшөөрөгдөх алдааны хувь нь **10%** байна.

> Энэ нь хугацаагаар тооцвол 12 секундийн эвдрэх эрхтэй тэнцэнэ: 120 × 10% = **12 секунд**.

## Мини chaos — Availability сценариог бодитоор турших

Chaos туршилтын availability-г зөвхөн хугацаагаар бус, нийт хүсэлтээс хэд нь амжилттай болсон гэдгээр тооцсон. Сервер 10 секунд зогссон үед хүсэлтүүд `connection refused` алдаатай буцсан тул олон хүсэлт амжилтгүй болсон. Иймээс 10 секундын зогсолт нь 12 секундын time-based error budget-ээс бага боловч request-based availability SLO-г зөрчих боломжтой.

### Бодит үр дүн

| Үзүүлэлт | Утга |
| :--- | ---: |
| Нийт хүсэлт | 5,745 |
| Амжилттай хүсэлт | 4,808 |
| Амжилтгүй хүсэлт | 937 |
| Request-based availability | **83.69%** |
| Зорилтот SLO | **≥ 90%** |

```text
4808 / 5745 × 100 = 83.69%
```

**Дүгнэлт:** Request-based availability нь 90%-ийн SLO-оос бага тул Availability SLO зөрчигдсөн байна.
